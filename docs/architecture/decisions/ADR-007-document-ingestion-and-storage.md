# ADR-007: Document ingestion, and where original files are kept

- **Status:** Proposed (S2-03). The choice of a local folder for originals (decision log Q8) was made on 2 Nov 2026; the rest awaits review by the platform owner.
- **Plain-language terms:** *Ingesting* a document means keeping an unchangeable copy of an approved file, recording its fingerprint (SHA-256: a short code that changes if one byte of the file changes), and reading its text page by page so it can be searched later. An *object store* holds files under names (keys). A *text layer* means a PDF's words are real, selectable text; a scanned page is only a picture and has none.
- **Decision:**
  - **Originals live in a local folder behind a small interface.** `infrastructure/storage` defines `ObjectStore` (`put`, `get`, `exists`); `LocalFolderStore` keeps files under `STORAGE_ROOT` (a volume in compose). Another store, for example SeaweedFS or any S3-compatible service, only has to implement the same three methods. Files are **write-once**: the same bytes under a key change nothing, different bytes under an existing key are refused. Keys are safe relative paths only (no `..`, no leading `/`).
  - **Keys come from the file's fingerprint:** `originals/<source_id>/<sha256>.pdf` and `extracted/<source_id>/<sha256>.json`. Storing the same file twice therefore writes the same bytes to the same name, which makes a retry after a failure harmless.
  - **One ingestion service, three entry points** (`features/documents/ingestion.py`): the upload endpoint, the corpus script (`scripts/ingest_corpus.py`) and tests. Order of work: check the request and the licence rule (ADR-002), read the text (a file that cannot be read leaves no trace), store the files, then write the database rows. The caller commits, after the audit event.
  - **Text extraction** (`features/documents/extraction.py`): pypdf in-process by default; Apache Tika behind the same interface when `EXTRACTION_ENGINE=tika`, with pypdf as the fallback if Tika is unreachable (ADR-003). Every page keeps its page number, because a citation must point at an exact page. The result records the engine, whether pages have text (`yes`, `partial`, `no`), a status (`ok`, `partial`, `failed`) and notes in plain words. Migration 0003 adds these fields to `document_versions`.
  - **Scans are kept but marked.** A PDF with no text layer is stored with status `failed` and a note that OCR is not available; nothing pretends it was searched. OCR is out of scope for Sprint 2.
  - **API.** `PUT /api/v1/sources/{source_id}/versions` (administrators only; the raw PDF is the body; refused with 409 if the source is not eligible) and `GET /api/v1/projects/{project_id}/documents` (project members only; includes the attribution text that must accompany any citation). The same file again returns 200 and changes nothing; a changed file becomes a new version and earlier versions are kept. Every outcome, refusals included, is written to the audit trail.
  - **Tika is pinned** to `apache/tika:4.2.0` in compose and CI. The page-aware reader was tested against that version. Tika 4 answers on `/rmeta/xml` with the content under `tk:content`; earlier versions used `X-TIKA:content`, and the reader accepts both.
- **Why:** Sprint 2's goal needs real documents with exact page references and a fingerprint, and the licence rule must hold at every step. A folder behind an interface is the simplest thing that works on a developer laptop and keeps the later move to an object store a change in one class.
- **Trade-offs and limits:**
  - **Files and database are not one transaction.** Files are written first and the database second, so a failure in between leaves harmless unreferenced files (same names on retry). The audit event is written before the commit, so a failed commit after a written event would leave an event for something not saved. This is rare; closing it needs the audit event and the document in one database transaction (see the S2-10 note in ADR-005).
  - **A local folder is a single machine.** Several API servers would need a shared volume or an object store.
  - **No virus scan, no page images, no tables as tables.** Text only. Table structure from Tika is flattened to lines.
  - **Administrators only may upload.** Reviewers and scientists cannot add documents; a different rule needs a decision.
  - **ADR-003 names `tika/tika:2.9.2-full`.** That is outdated (the `-full` image adds OCR, which is not used yet). This ADR supersedes it for the version.
- **Revisit when:** OCR is needed (a `-full` Tika image and Tesseract); more than one API server runs; the client names an object store; the review gate (S2-10) puts audit and data in one transaction; chunking and embeddings (S2-06) start reading the extracted text.
